# [About Secure Data Sharing](https://docs.snowflake.com/en/user-guide/data-sharing-intro)

# 1. ドキュメント概要（初学者向け）

このドキュメントは、Snowflake のデータ共有機能 **Secure Data Sharing** について説明しています。  
Snowflake では、**実際のデータコピーや転送を伴わずに、他の Snowflake アカウントとデータをリアルタイムで共有**できます。

これは、共有先（コンシューマー）がプロバイダー側のデータに直接アクセスできる仕組みであり、ストレージスペースを複製する必要がありません。共有は **安全かつ制御可能** で、共有されたデータは **読み取り専用** として扱われます。

## Snowflake 全体の中での位置づけ
Secure Data Sharing は、**組織間・アカウント間でのデータ連携・コラボレーション** を実現するための基本機能です。  
さらに、Snowflake Marketplace やデータ製品提供の基盤としても利用されます。

# 2. 原文に沿った内容整理（翻訳ベース）

## Secure Data Sharing の仕組み
Snowflake の Secure Data Sharing により、Snowflake アカウント内の **データベースオブジェクトを他の Snowflake アカウントと共有**できます。  
共有は、Snowflake の **サービスレイヤー** と **メタデータストア** を使い、**データのコピーや移動を行わずに実現**されます。

そのため、共有されたデータは **コンシューマー側のストレージを占有せず**、コンシューマーはそのデータに対してクエリを実行できます。

【補足】  
ここでいう「コピーなし共有」は、データそのものを相手のストレージに複製しないため、データ更新も共有先にすぐ反映されやすいことが特徴です（データの参照権限を共有するイメージです）。

---

## 共有対象のオブジェクト例
Snowflake では次のようなオブジェクトを共有できます：

- データベース
- テーブル
- 動的テーブル
- 外部テーブル
- 外部管理および管理された Apache Iceberg™ テーブル
- 外部管理された Delta Lake テーブル
- セキュアビュー / セキュアマテリアライズドビュー
- セマンティックビュー
- Cortex Search サービス
- ユーザー定義関数（UDF）（セキュア・非セキュア）
- モデル（USER_MODEL、CORTEX_FINETUNED、DOC_AI など）

【補足】  
共有できる対象は「テーブルだけ」ではなく、ビューや関数など **データ利用のための周辺オブジェクト** も含まれる点が特徴です。

---

## 共有の流れと基本概念

### 共有（Share）とは
**共有（Share）** は、Snowflake 内で共有されるオブジェクトへの **権限と情報をカプセル化した名前付きオブジェクト**です。

プロバイダーは、共有に対して次のいずれかで共有対象を追加できます：
- **データベースロール経由**
- **直接オブジェクトに対する権限付与**

その後、**1 つ以上のコンシューマーアカウントを共有に追加**することで、他アカウントと共有できます。

【補足】  
Share は「共有する対象（何を見せるか）と、見せ方（どの権限で見せるか）」をまとめた“共有の箱”のようなオブジェクトです。

### プロバイダーとコンシューマー

#### プロバイダー（Provider）
データを共有する側の Snowflake アカウントを指します。

- プロバイダーは、共有オブジェクトを作成できます。
- データベース内の特定オブジェクトへのアクセス権限を **細かく制御**できます。
- **複数の共有を作成可能**です。
- **1 つの共有に複数のコンシューマーアカウントを追加**することも可能です。

#### コンシューマー（Consumer）
共有からデータベースを作成した側のアカウントです。

- コンシューマーは、インポートした共有データベースを自分のアカウント内の他のデータベースと同じようにクエリできます。
- ただし、共有ごとに **1 つだけデータベースを作成**できます。

【補足】  
コンシューマー側では「共有からインポートしたデータベース」を作ることで、普段の SQL と同じ感覚で扱えます（ただし読み取り専用）。

---

## 使用状況メトリックとリーダーアカウント

### 使用状況メトリック
Snowflake Marketplace やリスト共有を使用する場合、コンシューマー側で共有データの **利用状況に関するメトリック** を確認できます。

【補足】  
共有データが「どれだけ使われているか」を把握するための指標として利用できます。

---

### リーダーアカウント（Reader Account）
**リーダーアカウント** は、Snowflake アカウントを持っていないユーザーにデータ共有を提供するための特別なアカウントです。

- リーダーアカウントは、プロバイダーが **作成・所有**します。
- プロバイダーの範囲で共有データにアクセスできます。
- ただし、読み取り専用であり、データ操作（INSERT/UPDATE/DELETE）などはできません。

【補足】  
「相手が Snowflake を契約していなくても、共有データを見せたい」という場面で利用されます。

# 3. 用語・概念のやさしい説明

| 用語 | 初学者向け説明 |
|---|---|
| Secure Data Sharing | データのコピーなしに、Snowflake アカウント間でデータを共有できる仕組み。 |
| プロバイダー（Provider） | データを他アカウントと共有する側の Snowflake アカウント。 |
| コンシューマー（Consumer） | 共有されたデータを受け取り利用する側の Snowflake アカウント。 |
| 共有（Share） | 共有の対象・権限・アクセス情報をまとめたオブジェクト。 |
| リーダーアカウント | Snowflake アカウントを持たないユーザーが共有データにアクセスできる特別アカウント。 |
| 読み取り専用 | コンシューマー側では共有されたデータを変更できない状態。 |

---

# 4. 注意点・制約（明記がある場合）
- 共有されたデータは **読み取り専用** です。データの変更や削除はできません。
- 共有されたデータは **コンシューマー側のストレージを占有しません**。ストレージ費用はプロバイダーの側にのみ発生します。
- 共有ごとにコンシューマー側で作成できるデータベースは **1 つだけ** です。

---

# 5. 初学者向けまとめ
- Secure Data Sharing は、**データコピーなしでアカウント間共有を可能にする仕組み** です。
- プロバイダーはデータを共有し、コンシューマーはそれを **読み取り専用** で利用します。
- 共有は **Share オブジェクト** として管理され、アクセス権限を細かく制御できます。
- **リーダーアカウント** を使えば、Snowflake アカウントを持たないユーザーにも共有可能です。
- 共有されたデータはコンシューマーのストレージを消費しません。
- 共有の利用状況メトリックを確認し、データ利用を分析できます。
- 共有されたデータベースは **1 つの Share につき 1 つ** だけコンシューマー側に作成できます。
