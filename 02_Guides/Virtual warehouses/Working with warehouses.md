# [Working with warehouses](https://docs.snowflake.com/en/user-guide/warehouses-tasks)

# 1. ドキュメント概要（初学者向け）

このドキュメントは、**Snowflake におけるウェアハウス（仮想ウェアハウス）に対して行える操作（タスク）**を詳しく説明しています。具体的には：

- ウェアハウスの **作成**
- **開始／再開**
- **一時停止**
- **サイズ変更**
- ウェアハウスを **使用する（セッションへの割り当て）**
- **管理権限の委譲**
- 管理ビューの確認方法（Snowsight での詳細確認）

といった一連の操作を、Snowflake Web UI（Snowsight / Classic Console）、SQL、Python API などを使って実行する方法を示します。

## Snowflake 全体での位置づけ
Snowflake では、ウェアハウス（仮想ウェアハウス） がクエリや DML/ETL 処理の計算を担う基礎リソースです。  
このページでは、その **管理タスク（開始・停止・設定変更など）** を実行する方法と、その挙動・注意点を公式仕様どおりに整理しています。

# 2. 原文に沿った内容整理（翻訳ベース）

## ウェアハウスタスクの全般
すべてのウェアハウスに関連するタスクは、Snowflake の Web UI（Snowsight または Classic Console）から、または DDL（SQL）コマンドを使って実行できます。

---

## ウェアハウスの作成
ウェアハウスを作成するには以下のインターフェイスが使えます：

- **Snowsight**
  - ナビゲーションメニュー → Compute » Warehouses » Warehouse を選択
- **Classic Console**
  - Warehouses » Create を選択
- **SQL**
  - `CREATE WAREHOUSE` コマンドを実行
- **Python API**
  - `WarehouseCollection.create` を使う

作成時に、ウェアハウスを **「開始済み（実行中）」** か **「一時停止」** のどちらで状態を始めるか選択できます。

- 「開始済み」で作成すると、Snowflake はすべてのコンピューティングリソースをプロビジョニングし、クレジットの消費を開始します。  
  → このプロビジョニングには時間がかかる場合があります。

---

## ウェアハウスの開始または再開
ウェアハウスは、初期作成時を含めていつでも開始または再開できます。  
停止したウェアハウスを再開するために使用できる方法も以下の通りです：

- **Snowsight UI**
- **Classic Console**
- **SQL**
  - `ALTER WAREHOUSE ... RESUME`
- **Python API**
  - `WarehouseResource.resume`

実行中のウェアハウスは **コンピューティングリソースを消費し続ける** ため、クレジットも消費されます。

- まれにプロビジョニングが一部失敗しても、利用可能なリソース分の消費が開始され、残りが正常にプロビジョンされると全体で消費が始まります。
- クレジットは **1 秒単位で請求** され、再開ごとに **最低 1 分分の請求が確定** します。

---

## ウェアハウスの一時停止
実行中のウェアハウスをいつでも一時停止できます。

- 一時停止すると、すべてのコンピューティングリソースが **シャットダウン** され、クレジット消費が停止します。
- 一時停止中に実行中だったステートメントは止まりませんが、完了後にリソースが閉じられます。

操作方法は UI / SQL / Python API で同様です。

### SQL
```sql
ALTER WAREHOUSE <name> SUSPEND;
```

---

## ウェアハウスのサイズ変更
ウェアハウスは **実行中でも一時停止中でも** サイズを変更できます。

### 実行中のサイズ変更
- <span style="color: red;">クエリの処理や DML/ETL 処理中でも、計算リソースの増減（サイズ変更）が可能です。</span>
- <span style="color: red;">追加されたリソースはプロビジョン完了後に利用され、現在実行中のステートメントには影響しません。</span>
- 既存のリソース削減は、現在のステートメントに利用されなくなってから適用されます。

### 一時停止中のサイズ変更
- ウェアハウスが **一時停止中でもサイズの変更** は可能です。
- この場合、次回再開時に指定サイズでプロビジョニングが行われます。

操作方法は UI / SQL / Python API で同様です。

### SQL 例
```sql
ALTER WAREHOUSE <name> SET WAREHOUSE_SIZE = SMALL;
```

---

## ウェアハウスの使用
Snowflake でクエリや DML ステートメントを実行するには、ウェアハウスが **稼働（実行中）しており、現在のセッションで選択されている必要** があります。

- セッションには **1 つの現在のウェアハウス** しかありません。
- SQL コマンド `USE WAREHOUSE` や Python API `WarehouseResource.use_warehouse` で指定・変更できます。

---

## ウェアハウス管理の委譲（Role Delegation）
- `ACCOUNTADMIN` ロールにはデフォルトで、すべてのウェアハウスに対する管理権限があります。
- 別ロールに管理権限を委譲したい場合は、`MANAGE WAREHOUSES` 権限を付与します。
- この権限は、該当ロールに対してウェアハウスの **変更・停止・再開・説明・その他操作** を許可します。

---

## Snowsight でのウェアハウス詳細レビュー
Snowsight では、ウェアハウステーブルを使って詳細情報を確認できます。確認可能な項目の例：

- Name（名前）
- Status（状態：Started / Resuming / Suspended）
- Size（サイズ）
- Clusters（クラスター数）
- Running（実行中ステートメント数）
- Queued（キュー待ちステートメント数）
- Owner（所有者ロール）
- Auto Suspend / Auto Resume 設定
- Query Acceleration Service（QAS）設定
- Scaling Policy（スケーリングポリシー）
- Created（作成日時）

また、Warehouse Activity で負荷グラフを確認し、遅延の原因調査にも役立ちます。

---

# 3. 注意点・制約（明記がある場合）
- ウェアハウスを **再開するごとに最低 1 分分のクレジット請求が確定** します。
- プロビジョニング中の **一部リソースが失敗した場合でも消費が発生する可能性** がありますが、修復後に全面開始されます。
